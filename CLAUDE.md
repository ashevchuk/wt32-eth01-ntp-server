# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Network NTP server firmware for the WT32-ETH01 board (ESP32, wired Ethernet), built with ESP-IDF. The repository holds a minimal ESP-IDF project skeleton (`main/main.c` only logs a start message); the sections below record the hardware and toolchain facts the code must be written against.

## Hardware

| Peripheral | Interface | Pins |
|---|---|---|
| DS3231M RTC | I2C | SDA IO33, SCL IO32 |
| HD44780 20x4 LCD via PCF8574 backpack | I2C (same bus as the RTC) | SDA IO33, SCL IO32 |
| u-blox M8N GNSS with an active antenna | UART, 115200 baud, NMEA and UBX | TX IO17, RX IO5 |
| GNSS PPS | GPIO input | IO35 |
| Reset button (to GND, internal pull-up): hold 5 s = Ethernet back to DHCP | GPIO input | IO14 |
| DS18B20 sensors (external power, 4.7 kΩ pull-up) | 1-Wire bus | IO4 |

- The RTC and the LCD share one I2C bus; their addresses differ (DS3231 `0x68`, PCF8574 `0x27` or `0x3F`).
- IO35 is input-only and has no internal pull-up.
- Ethernet on this board uses GPIO0 as the RMII clock input and GPIO16 as the oscillator enable; do not reuse them.
- LCD backpacks are usually powered from 5 V, and their I2C pull-ups may pull the bus above the ESP32's 3.3 V tolerance.

## Architecture

- `gnss.c` parses RMC sentences (checksum-verified, fix status `A` only) and timestamps PPS edges in an ISR. The pairing is time-critical: RMC describes the second that began at the previous pulse, so `pps_task` takes the pending RMC at the next pulse, adds one second and calls the `gnss_start` callback, discarding RMC samples that arrived more than 500 ms after the previous pulse.
- `main.c` uses that callback to write the RTC at first fix and then hourly.
- `ntp_clock.c` keeps three anchors (unix time at an `esp_timer` instant): GNSS, network and RTC, and extrapolates from the best one. Priority: GNSS while it is less than 10 minutes old (stratum 1, refid `GPS`), then the network while it is less than 45 minutes old (stratum = upstream + 1, refid = upstream IPv4), otherwise the newest anchor of any kind (stratum 10, refid `LOCL`); with no anchor the server reports stratum 16, LI=3 and zero timestamps. A task re-anchors to the RTC at the instant its seconds register changes, once a minute, while neither GNSS nor the network is usable.
- `upstream.c` is a minimal SNTP client (no lwIP SNTP): it resolves the configured server (default `pool.ntp.org`, NVS key `upstream`, empty disables it), takes four samples 0.5 s apart every 15 minutes and keeps the one with the lowest round trip, applying half the round trip as correction. It also records how far GNSS time was from the upstream and, when GNSS is not the source, writes the RTC on a second boundary at most once an hour.
- `leap.c` polls `UBX-AID-HUI` once a minute and keeps the GPS-UTC offset and any scheduled leap second as an `esp_timer` instant. The usual `UBX-NAV-TIMELS` is not used because this receiver's firmware (SPG 2.01, protocol 15) never answers it; `AID-HUI` reports the satellite-broadcast offset, the scheduled offset and the week and day of the change. The week field is expanded to a full week number near the present, so it is meaningful only while the scheduled offset differs from the current one; `ntp_server.c` asks it for the LI bits and `/api/status` (`gnss.leap`) shows the state. The receiver reports an inserted second as `23:59:60`, and `gnss.c` does not add a second to it, so the anchor after it is midnight. During the inserted second itself the clock is not stepped back, so replies in that second are one second ahead.
- `ubx.c` frames UBX messages out of the same UART byte stream as NMEA (`ubx_feed` is called first for every byte) and offers `ubx_poll`/`ubx_set`. `gnss_config.c` uses it a few seconds after boot to make the M8N use the stationary dynamic model (`UBX-CFG-NAV5`) and, once the user has set them in the web page, the antenna cable delay and an additional PPS delay (`UBX-CFG-TP5`). It reads the current values first, writes only on a difference and then saves to the receiver's memory (`UBX-CFG-CFG`), because every save costs flash cycles. If the receiver does not answer, the UART's UBX input is probably disabled.
- `ntp_server.c` answers NTP client requests (mode 3, versions 1-4) on UDP 123 from a single task that keeps one socket per interface (Ethernet and Wi-Fi), each bound to that interface's address and followed as the address changes, and waits on them with `select`. A socket on `INADDR_ANY` would answer from whichever interface lwIP finds first, and a client such as `ntpdate` drops a reply that does not come from the address it asked; binding to the address makes lwIP's source-based routing send the reply out of the same interface; the receive timestamp is taken right after `recvfrom`, the transmit timestamp right before `sendto`. The leap indicator is 1 or 2 only during the UTC day that ends with a leap second scheduled in the receiver (`leap.c`); it is 0 otherwise, also for network-sourced time, whose upstream indicator is not forwarded.
- `gnss.c` also keeps a status snapshot (GGA/GSA/GSV/RMC: fix, satellites, DOP, position) returned by `gnss_get_status`.
- `gnss.c` reads three periodic UBX messages through `ubx_set_handler`: `NAV-SAT` (per satellite: signal, elevation, azimuth, quality indicator, used in the fix, ephemeris and almanac; served at `/api/gnss/satellites` in chunks because it does not fit the status buffer), `NAV-PVT` (fix type, time validity and the receiver's time accuracy estimate, in `gnss.pvt`) and `MON-HW` (antenna supervisor, interference indicator, AGC, in `gnss.hardware`). `gnss_config.c` makes the receiver send them: this module has UBX output disabled on UART1, and with that setting it answers polls but never sends periodic messages, so it enables UBX in `CFG-PRT` and the message rates with `CFG-MSG`, waits 300 ms after the port change and saves only when something changed. It also switches on the receiver's interference monitor (`CFG-ITFM`, enable bit only), because without it `MON-HW` reports the jamming state as unknown; the monitor detects interference, not spoofing, which this firmware (protocol 15) cannot detect. `pps_task` accepts the GNSS second only when NAV-PVT, if it is arriving, reports the time as valid and resolved and its accuracy estimate, when known, is within 1 ms; without NAV-PVT, RMC alone decides, and an unknown accuracy does not reject. It also keeps statistics of the PPS interval over the last minute (`gnss_get_pps`, in `gnss.pps`: offset in ppm of the ESP32 clock against the pulses, standard deviation and range; intervals more than 10 ms off are treated as missed pulses and ignored). This receiver speaks NMEA 4.0 (it accepts 4.1 and 4.11, which would renumber satellites and is not needed); NMEA only supplies RMC, GGA, GSA and the in-view count. Elevation and azimuth stay unknown until the receiver has orbit data for a satellite, so the sky plot shows only satellites with a direction while the bar chart shows all of them. `HTTP_MAX_URI_HANDLERS` is 24; each method of a URI takes a slot.
- All sockets come from one lwIP pool (`CONFIG_LWIP_MAX_SOCKETS=16` in `sdkconfig.defaults`): the HTTP server may hold 8 connections and evicts the least recently used one when full, because browsers keep several idle keep-alive connections per tab and would otherwise exhaust the pool, which also makes Munin and every other request fail with a connection reset.
- `web.c` serves `main/web/index.html` (embedded via `EMBED_TXTFILES`) and `GET /api/status`. The web interface has no authentication by owner's decision. JSON is written by hand with `snprintf` because IDF 6.0 no longer ships cJSON in core; adding it would be a new managed dependency.
- `settings.c` wraps NVS (namespace `ntp`) and applies the stored POSIX TZ string via `setenv`/`tzset`. Only the LCD clock and the web page use local time; NTP, RTC and the anchor always work in UTC, so use `timegm`/`gmtime_r` there, never `mktime`.
- Network settings (hostname, DHCP/static addressing for Ethernet and for Wi-Fi, Wi-Fi STA credentials) are one NVS blob in `settings.c`, which discards a stored blob of a different size, so changing `network_settings_t` resets them to the defaults; validated by `settings_network_error`, and applied only at boot by `eth_start` and `wifi_start`; `POST /api/reboot` restarts the device. `static_ip.c` applies a fixed address to either interface. Wi-Fi gets route priority 10 so Ethernet (50) stays the default route. That priority only decides the default route: lwIP sends a packet that has no source address (DNS queries, the SNTP client's socket) through the first interface whose subnet matches, and the newest interface is listed first, so with both interfaces in one subnet the later one wins. `app_main` therefore starts Wi-Fi before Ethernet, and Ethernet's netif is created last on every retry too. Wi-Fi password is stored in plain NVS and never returned by the API.
- OTA: `ota.c` handles `POST /api/ota` (raw image as body), accepts only images whose app descriptor has this project's name, writes the next slot and reboots. Two 1.875 MB slots in `partitions.csv` on 4 MB flash; `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE` makes the bootloader revert an image that resets before `ota_confirm_running_image()` runs at the end of `app_main`. Bump `PROJECT_VER` in the top-level `CMakeLists.txt` for each release so the running slot can be told apart.
- `sensors.c` bit-bangs 1-Wire on IO4 in a task pinned to core 1: interrupts are masked during every time slot, and keeping that on core 1 leaves the PPS interrupt on core 0 undisturbed. It rescans the bus every 60 s (ROM search, CRC-checked), reads all DS18B20s every 10 s with one broadcast convert, and keeps unplugged sensors in the table as absent. Sensor names are Munin field names (`[A-Za-z_][A-Za-z0-9_]*`), stored per ROM code in NVS. An empty name restores the default `ds18b20_<serial>`. A sensor can also have a label (separate NVS key, same layout as the names), which `munin.c` prints as the field's `.label` while the name stays the field name that identifies the RRD; without a label the name is shown. Whether a sensor appears in Munin is a separate per-sensor flag (checkbox on the page, `munin=1|0` on `POST /api/sensors`), kept as a list of ROM codes in its own NVS key and off for a new sensor.
- `reset_button.c` polls IO14; a 5 s hold stores `eth_static = false` and restarts, and does nothing when Ethernet already uses DHCP. Wi-Fi settings and hostname are left alone.
- `munin.c` is a munin-node on TCP 4949 with one plugin (name stored in NVS, default `environment`, changeable at runtime), one field per sensor that is ticked for Munin (`U` when it has no fresh reading), and nine built-in GNSS plugins (`gnss_satellites`, `gnss_signal`, `gnss_dop`, `gnss_pps_offset`, `gnss_pps_jitter`, `gnss_time_accuracy`, `gnss_interference`, `gnss_jamming_state`, `gnss_agc`) defined in a table in `munin.c`, whose names are reserved: the configurable plugin name cannot equal them. They report `U` when the receiver has been silent for 5 s, when there is no fix (DOP) or no PPS statistics yet. The task stack is 6 KB because the fetch handlers build a satellite list on it. It has no access control.
- `POST /api/time` (form field `utc`) writes the RTC and calls `ntp_clock_anchor_local`, which makes the server report stratum 10; it is rejected with 409 while GNSS or network time is available, because those anchors outrank it.
- `eth.c` also samples receive-error counters once a second: the LAN8720 symbol error counter (PHY register 26, meaningful only on a 100 Mbit link) and the EMAC missed-frame and FIFO-overflow counters. They and the negotiated speed and duplex appear in `/api/status` and on the Ethernet card. Missed/overflow staying at zero while packets are lost means the loss happens on the wire, not in the ESP32's buffers. `/api/status` also reports the last reset reason.
- Watchdogs: `sdkconfig.defaults` makes the task watchdog panic (and therefore reboot) after 20 s; by default it only prints a warning. `ntp_server`, `bigclock`, `sensors` and `ntp_rtc` subscribe to it and feed it every loop pass, so the timeout must exceed the longest pass (the sensor task sleeps 10 s per pass). `ntp_server` uses a 1 s receive timeout so a quiet network does not look like a hang. Tasks that legitimately wait indefinitely (`pps`, `nmea`, `munin` accept, `upstream`) are not subscribed, and a stuck HTTP server task is not detected. `system.reset_reason` shows `task watchdog` after such a reset. `main.c` also counts every boot per reset reason in NVS (`settings_record_reset`, blob of 16 counters indexed by `esp_reset_reason_t`); `/api/resets` returns the non-zero counts and a POST clears them, and the System card shows them, so a `brownout` or watchdog reset stays visible after later clean restarts.
- Crash dumps: `CONFIG_ESP_COREDUMP_ENABLE_TO_FLASH` stores the core dump of a panic or watchdog reset in the 128 KB `coredump` partition after `ota_1`; adding that partition changed the partition table, which needs one flash over the serial port (`scripts/flash-serial.sh`), after which OTA works as before. `GET /api/coredump` downloads the image, `POST /api/coredump` erases it, and the System card shows its size and the first 9 hex digits of the firmware's SHA-256. A dump can only be decoded with the ELF of the exact build that crashed, so `scripts/build.sh` copies `build/ntp.elf` to `build/elf/<16 hex digits of its SHA-256>.elf`; decode with `. /opt/esp-idf/export.sh; esp-coredump info_corefile --core coredump.bin --core-format raw build/elf/<sha>.elf`.
- Logging: `sdkconfig.defaults` sets the application log level to WARN (`LOG_MAXIMUM_EQUALS_DEFAULT` also strips the INFO and DEBUG calls from the image) and the bootloader to ERROR, so the UART carries only warnings, errors and panic output; state worth reading lives in `/api/status`, `/api/resets` and the crash dump instead. For a debugging session set `CONFIG_LOG_DEFAULT_LEVEL_INFO` in the defaults temporarily. The bootloader level only changes after a flash over the serial port, and the first lines of every boot (`ets ...`, `rst:`, `load:`) come from the chip's ROM, which ESP-IDF cannot silence on the ESP32.
- Startup is fault tolerant: `app_main` logs a component that does not start (`startup.c` keeps the list, shown as "Startup" on the System card and in `system.failed`) and carries on, because an `ESP_ERROR_CHECK` there reboots the device in a loop and, since `ota_confirm_running_image()` is never reached, makes the bootloader roll back a good image. Only NVS initialisation is fatal. Dependents are skipped when their base failed (the clock display without the LCD, the receiver configuration and leap seconds without the GNSS UART), and `rtc_read`/`rtc_write` return `ESP_ERR_NOT_FOUND` without a device. A failed Ethernet bring-up releases what it created (the driver's `uninstall` and the MAC and PHY `del` are the caller's job) and is retried every 10 s in `eth_retry`, cycling the oscillator each time, until it works; a failed RTC write is retried after a minute.
- `i2c_bus.c` owns the single I2C bus; `lcd.c` and `rtc.c` attach devices to it.
- `bigclock.c` polls the RTC every 100 ms and renders local time `HH:MM:SS` in 3x4-cell digits built from 8 custom characters, ported from lcdproc's BigClock (`clients/lcdproc/chrono.c`, `server/drivers/adv_bignum.c`); it redraws only changed digits, and the colons blink with second parity.
- DS3231 oscillator-stopped flag: `rtc_read` returns `ESP_ERR_INVALID_STATE` while it is set; `rtc_write` clears it.

## Toolchain

- ESP-IDF is installed at `/opt/esp-idf`; its tools are in `~/.espressif` (Python envs for IDF 5.5 and 6.0; the skeleton was built with 6.0). `idf.py` is not on `PATH` until the environment is exported: `. /opt/esp-idf/export.sh`.
- The board is attached as `/dev/ttyACM0` (group `uucp`, which the user belongs to).

## Commands

```
scripts/build.sh                      # idf.py build (runs set-target esp32 when sdkconfig is missing)
scripts/flash-serial.sh [port]        # flash over serial, default /dev/ttyACM0; needed after partition changes
scripts/flash-ota.sh <host> [image]   # upload build/ntp.bin to the running device and wait for the new slot
idf.py menuconfig                     # after sourcing /opt/esp-idf/export.sh
```

`flash-ota.sh` exits non-zero when the upload is rejected, the device does not return, or it returns on the same slot (the new image was rolled back).

`sdkconfig` is generated from `sdkconfig.defaults` (flash size, partition table, rollback); change the defaults and rerun `idf.py set-target esp32` rather than editing `sdkconfig` by hand. Moving to this partition layout required one flash over the serial port.
